## 一、核心心智模型：文本处理就是数据流

文本处理的本质不是"背命令"，而是把文本当成一条**流（stream）**，每个命令是一个加工环节，上一段的输出通过管道接下一段的输入。

- 三个标准流：标准输入 `stdin(0)`、标准输出 `stdout(1)`、标准错误 `stderr(2)`，重定向就是改变它们的指向；详见 [[Linux01d 重定向 管道与 xargs]]。
- 管道 `|`：在内存中把前一段的 `stdout` 接到下一段的 `stdin`，不产生中间文件；**默认不传 `stderr`**。
- 一条典型流水线的数据流：

```mermaid
flowchart LR
    A[原始日志] --> B[grep 过滤行]
    B --> C[sed 清洗替换]
    C --> D[awk 切列统计]
    D --> E[sort/uniq 排序去重]
    E --> F[输出屏幕或写文件]
```

选工具前先问三个问题：**要不要只保留某些行？要不要改内容？要不要切列或算总数？** 答案分别对应 grep、sed、awk。

## 三、工具选型决策（本篇重点）

### 3.1 grep / sed / awk 怎么选

| 需求 | 选 | 理由 |
|---|---|---|
| 只保留或排除某些行 | grep | 行过滤，整行保留，不切字段 |
| 改内容、替换、删行 | sed | 流式行编辑，默认只预览、`-i` 才改原文件 |
| 切列、计数、条件判断、求和 | awk | 按分隔符切字段，内置数组与逻辑 |

### 3.2 几组容易混的对比

- **find vs grep**：find 找**文件**，grep 找文件**内容**。
- **cut vs awk**：cut 只认单个固定分隔符，遇到连续空格会切出空字段；awk 自动忽略连续空白，更灵活。
- **sort+uniq vs awk 数组**：传统管道每段直观、便于单独调试；awk 一个命令就能聚合，脚本更短。
- **传统管道 vs awk 一把梭**：awk 简洁但逻辑全堆在一处；多段管道可读性和可调试性更好，复杂任务优先分段。

### 3.3 动手前的决策顺序

1. 明确目标：要行、要字段、还是要统计数；
2. 定位字段：确认目标在第几列（先 `head` 看几行）；
3. 选最小工具：能用一个命令解决就不堆管道；
4. 先预览再落盘：输出确认无误后，才加重定向或 `sed -i`。

### 4.2 字段定位

按空格切分后，本样例最常用的三个字段：`$1` 来源 IP、`$7` 请求路径、`$9` 状态码。

```bash
awk '{print $1}' access.log | head -3
```
```text
203.0.113.5
203.0.113.5
198.51.100.7
```

```bash
awk '{print $7, $9}' access.log | head -3
```
```text
/index.html 200
/css/style.css 200
/admin 404
```

### 4.3 五个真实任务

**任务 1：统计 Top 3 来源 IP**

awk 方案：
```bash
awk '{ip[$1]++} END{for(i in ip) print ip[i], i}' access.log | sort -nr | head -3
```
```text
5 203.0.113.5
4 198.51.100.7
2 45.76.12.90
```

传统管道方案（结果一致）：
```bash
cut -d' ' -f1 access.log | sort | uniq -c | sort -nr | head -3
```
```text
      5 203.0.113.5
      4 198.51.100.7
      2 45.76.12.90
```

**任务 2：统计 HTTP 状态码分布**

```bash
awk '{s[$9]++} END{for(i in s) print s[i], i}' access.log | sort -nr
```
```text
8 200
3 404
1 502
1 500
1 301
```

**任务 3：列出所有 4xx/5xx 错误请求（状态码 + IP + 路径）**

```bash
awk '$9>=400 {print $9, $1, $7}' access.log
```
```text
404 198.51.100.7 /admin
404 198.51.100.7 /admin/login
500 203.0.113.5 /api/data
502 45.76.12.90 /admin/config
404 45.76.12.90 /.env
```

**任务 4：统计接口访问量 PV，取 Top 5**

```bash
awk '{p[$7]++} END{for(i in p) print p[i], i}' access.log | sort -nr | head -5
```
```text
2 /index.html
2 /api/data
2 /
1 /robots.txt
1 /favicon.ico
```

**任务 5：一条完整流水线——错误请求的路径 Top**

```bash
awk '$9>=400 {print $7}' access.log | sort | uniq -c | sort -nr
```
```text
      1 /api/data
      1 /admin/login
      1 /admin/config
      1 /admin
      1 /.env
```

### 4.4 通用流水线模板

```text
清洗 → 过滤 → 提取字段 → 统计 → 排序取 Top
sed      grep     awk        sort/uniq   sort -nr | head
```

可迁移到 Top 访问 IP、状态码分布、接口 PV、错误日志分析等场景；更多任务走法见 [[Linux01f 日志统计综合实战]]。

## 五、高频易错点与安全纪律

### 5.1 最容易翻车的 8 个点

| # | 易错点 | 正确认知 |
|---|---|---|
| 1 | `>` 写文件 | 会先清空文件，哪怕命令随后失败；重要文件先备份 |
| 2 | `2>&1` 顺序 | 必须放在 `> file` 之后，写反了 stderr 仍打印屏幕 |
| 3 | uniq 不排序 | uniq 只合并相邻重复行，必须先 `sort` |
| 4 | `sed -i` 直接上 | 先不加 `-i` 预览，确认后用 `sed -i.bak` 留备份 |
| 5 | `kill -9` 滥用 | 先 `kill`(15) 让进程优雅退出，无效再 `-9` |
| 6 | 管道传 stderr | 管道只传 stdout，需要时 `2>&1 |` 或 `|&` |
| 7 | 文件名带空格 | 用 `find -print0 | xargs -0`，不要按空格硬切 |
| 8 | awk 比较与赋值 | 判断相等用 `==`，`=` 是赋值，别写混 |

完整 18 条易错点见 [[Linux01f 日志统计综合实战]]。

### 5.2 三条安全纪律

1. **先预览后落盘**：任何写操作前，先在屏幕确认输出；
2. **改文件先备份**：`sed -i.bak`、重要配置先 `cp` 一份；
3. **最小信号原则**：终止进程从默认 15 开始，不直接上 `-9`。
