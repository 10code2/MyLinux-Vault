## 二、Linux 基础

### 1. 软链接 vs 硬链接

| 对比项 | 软链接（symbolic link） | 硬链接（hard link） |
|---|---|---|
| 本质 | 指向文件路径的快捷方式 | 和原文件共用同一个 inode |
| 删除原文件 | 链接失效（悬空） | 仍可访问（inode 引用数-1，不为 0 不删） |
| inode | 有自己独立的 inode | 和原文件同一个 inode |
| 跨文件系统 | 可以 | 不可以（inode 号只在同一文件系统内唯一） |
| 链接目录 | 可以 | 不可以（防止循环） |
| 创建命令 | `ln -s 原文件 链接` | `ln 原文件 链接` |

**面试要点**：说出 inode、跨文件系统、目录这三个区别点就满分。

---

### 2. Linux 启动流程

```
BIOS/UEFI 自检 → MBR/GPT 引导 → GRUB 启动菜单 → 加载 Linux 内核
→ 第一个进程 init/systemd（pid=1）→ 按运行级别启动服务 → 出现登录界面
```

**关键词**：GRUB、内核、systemd（pid=1）。WSL 里 pid1 是 init 不是 systemd，真实服务器是 systemd——提一句显得有实操经验。

---

### 3. find vs grep

| 命令 | 搜索对象 | 典型用法 |
|---|---|---|
| `find` | 文件名/路径/属性 | `find . -name "*.log" -mtime +7`（找 7 天前的日志） |
| `grep` | 文件内容 | `grep -r "ERROR" /var/log/`（递归搜错误） |

---

### 4. 查看高 CPU / 高内存进程

```bash
# CPU 最高 5 个（非交互，脚本可用）
ps aux --sort=-%cpu | head -6

# 内存最高 5 个
ps aux --sort=-%mem | head -6

# 交互式：top 里按 P（CPU排序）/ M（内存排序）
```

**面试要点**：top 是交互式，脚本里用 ps。

## 三、Shell 脚本

### 1. 特殊变量

| 变量 | 含义 |
|---|---|
| `$?` | 上一条命令的退出码（0=成功，非0=失败） |
| `$#` | 脚本/函数的参数个数 |
| `$@` | 所有参数（不加引号会被空格拆分） |
| `"$@"` | 所有参数，保留每个参数的独立边界（带空格的参数不被拆碎） |
| `$0` | 脚本名 |
| `$$` | 当前进程 PID |

---

### 2. awk 统计 nginx 状态码分布

```bash
awk '{print $9}' access.log | sort | uniq -c | sort -rn
```
- `$9` = 状态码列
- `sort | uniq -c` = 分组计数
- `sort -rn` = 按数量降序

**awk 工作原理**：逐行读取 → 按分隔符（默认空格）切分字段 → 匹配模式 → 执行动作。

---

### 3. check_port 函数（手写代码题）

```bash
check_port() {
    if ss -tlnp 2>/dev/null | grep -q ":$1 "; then
        return 0
    else
        return 1
    fi
}
```

**易错点**：
- ❌ `if $(ss ... | grep $1)` —— `$()` 是命令替换，if 判断的是输出内容不是退出码
- ✅ `if ss ... | grep -q ...` —— if 后面直接跟命令，判断退出码
- `grep -q` 静默模式，只返退出码不打印内容
- `":$1 "` 前后加冒号空格，避免查 80 误匹配 8080

---

### 4. Shell 调试方法（必背）

| 方法 | 作用 |
|---|---|
| `bash -x script.sh` | 跟踪执行，打印每条命令和展开结果 |
| `set -x` | 脚本内开启跟踪（`set +x` 关闭） |
| `set -e` | 任何命令返回非 0 立即退出（防止错误蔓延） |
| `set -u` | 使用未定义变量时报错（防拼写错误） |
| `set -euo pipefail` | 生产脚本标配（e+u+管道失败也报错） |

**面试要点**：说 `bash -x` 和 `set -e` 就及格，说 `set -euo pipefail` 加分。注意 `test` 是条件测试命令，不是调试方法。

## 四、Nginx

### 1. 502 vs 504

| 状态码 | 含义 | 原因 | 排查方向 |
|---|---|---|---|
| 502 Bad Gateway | 网关错误 | nginx 连不上后端 | `ss -tlnp` 看后端在不在、端口对不对、防火墙 |
| 504 Gateway Timeout | 网关超时 | nginx 连上了后端但后端响应太慢 | 后端日志、`$upstream_response_time`、数据库查询、CPU/内存 |

---

### 2. 负载均衡算法

| 算法 | 说明 |
|---|---|
| 轮询 round-robin | **默认**，轮流分配 |
| 加权轮询 weight | `server x weight=3`，性能好的多分 |
| ip_hash | 按客户端 IP 哈希，同一用户固定到同一后端，**解决 session 保持问题** |
| least_conn | 优先发给当前连接数最少的后端 |

第三方模块：fair（响应时间）、url_hash。

---

### 3. location 匹配优先级（必背）

从高到低：
```
= 精确匹配  >  ^~ 前缀匹配  >  ~ 区分大小写正则  >  ~* 不区分大小写正则  >  普通前缀匹配
```

**口诀**：等号最硬，前缀其次，正则随后，普通兜底。

| 修饰符 | 示例 | 说明 |
|---|---|---|
| `=` | `location = /login` | 只匹配 `/login`，完全相等 |
| `^~` | `location ^~ /static/` | 匹配 `/static/` 开头，匹配后不再检查正则 |
| `~` | `location ~ \.png$` | 区分大小写正则 |
| `~*` | `location ~* \.png$` | 不区分大小写正则 |
| 无 | `location /api/` | 普通前缀匹配 |

## 五、监控巡检与项目

### 1. 巡检脚本退出码设计

`0=正常 / 1=告警 / 2=严重错误`——这是 Nagios/Zabbix 监控插件的标准退出码规范。监控系统通过退出码判断状态，不需要解析文本输出。

---

### 2. crontab 执行 vs 手动执行

**核心区别：环境变量不同。** crontab 的 PATH 只有 `/usr/bin:/bin`，交互式 shell 的 PATH 更全。导致脚本手动跑正常、定时执行报 `command not found`。

**解决**：脚本头部显式声明：
```bash
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
```

其他区别：crontab 没有交互终端，不能用需要 TTY 的命令；当前工作目录是用户 home 目录，不是脚本所在目录。

---

### 3. 邮件告警设计思路

1. 巡检结束时判断退出码，非 0 则调用告警函数
2. 用 `mailx`/`sendmail` 发邮件，内容含：时间、主机名、巡检摘要、具体错误项
3. 配置区加 `ALERT_EMAIL` 变量
4. 告警抑制：同一问题 1 小时内不重复发（避免刷屏）

```bash
if [ "$ERROR_COUNT" -gt 0 ] || [ "$WARN_COUNT" -gt 0 ]; then
    echo "巡检异常：通过$PASS_COUNT 告警$WARN_COUNT 严重$ERROR_COUNT" | \
        mail -s "【告警】主机巡检异常" "$ALERT_EMAIL"
fi
```

## 六、场景排障（面试重点）

### 1. 网站打不开——分层排查法

```
客户端层：ping 域名 → nslookup 解析 → telnet 端口 → 浏览器 F12 看状态码
网络层：  iptables/安全组有没有挡端口 → 路由通不通
服务层：  ss -tlnp 看端口 → service nginx status → nginx -t 看配置
应用层：  tail -f error.log → curl localhost 自测 → 后端服务状态
```

**面试要点**：按"客户端→网络→服务→应用"四层说，显得思路清晰。

---

### 2. df 满但 du 看不到大文件

**根因：已删除的文件仍被进程占用，句柄没释放，磁盘空间不回收。**

```bash
lsof | grep deleted    # 找出被删除但仍被占用的文件
```
解决：重启占用进程，或 `> /proc/<pid>/fd/<fd>` 清空文件句柄。

其他可能：挂载点覆盖（新分区挂载到有文件的目录，原文件被遮住）、稀疏文件。

---

### 3. load 高但 top 看不到高 CPU 进程

**根因：D 状态进程（不可中断睡眠），通常在等 IO（磁盘/网络）。** D 状态不消耗 CPU，但会计入 load average，所以 load 高而 CPU 使用率低。

```bash
top                          # 看状态列有没有大量 D
ps aux | awk '$8=="D"'       # 找出 D 状态进程
iostat -x 1 3                # 看磁盘 IO（%util 接近 100% = IO 打满）
```

**面试关键词**：D 状态、iostat、IO 瓶颈。

## 七、计算机网络

### TCP 为什么是三次握手不是两次

1. **确认双方收发能力**：两次握手只能确认服务端的收发能力，无法确认客户端的接收能力；三次后双方都确认了对方收发正常。
2. **防止失效连接**：防止已失效的连接请求报文突然又传到服务端，导致错误建立连接浪费资源。
